# ТЕСТОВЫЕ СЦЕНАРИИ (маппинг из Use Case)

Система: «rabbit.lab» — интерактивный конструктор RabbitMQ (Simulator-standalone).
Покрываются Use Case: 01–10 (см. файлы `uc01_…`–`uc10_…`).
Правило маппинга: MSS каждого UC → базовый тест-сценарий; каждое расширение → негативный/альтернативный тест-сценарий; трассируемость в «Примечании» в формате `UC-NN/расширение`.

| ТС-01 | Выбор учебного сценария direct | UC-01/1–6 | Студент выбирает сценарий 01 (direct) | Список сценариев открыт | Топология shop.direct + очереди orders/audit/payments загружена, метрики 0, задача и 4 проверки отображены | MSS UC-01 |
| ТС-02 | Восстановление сохранённого состояния сценария | UC-01/1a | Студент выбирает сценарий с сохранением, подтверждает «восстановить» | В localStorage есть состояние сценария | Выполнен use case 06, топология восстановлена из сохранения | UC-01/1a → UC-06 |

## Проверки учебных сценариев (из встроенных checks платформы)

Каждый учебный сценарий содержит встроенные проверки, которые система считает автоматически; тест-сценарии ТС-04/07/10/29 должны завершаться прохождением всех проверок выбранной топологии:

| Топология | Проверки (4–5 шт.) |
|---|---|
| 01 direct | Опубликовано order.created; orders получила; audit получила; payments не получила |
| 02 fanout | Опубликовано; email, inventory, analytics получили |
| 03 topic | Опубликовано order.created.eu; eu.orders и all.orders получили; us.orders и payments не получили |
| 04 DLQ | Опубликовано; orders получила; nack сделан; orders пуста; orders.dlq получила |
| 05 retry | Опубликовано; nack в work; retry приняла; у retry есть TTL и DLX; work получила после TTL |
| 06 headers | Опубликовано с type=order и region=eu; eu.orders и audit получили; priority.orders не получила |
